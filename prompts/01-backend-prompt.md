## Context

You are working on `chess-one-backend` — Node.js + Express 5 + Prisma 7 (PostgreSQL) + Socket.IO + chess.js + zod.
Prisma config file is `prisma7.config.ts` (schema at `prisma/schema.prisma`).
API responses use `success(res, data)` / `error(res, code, message, status)` from `src/utils/response.js`.
Auth uses `requireAuth` from `src/middleware/auth.middleware.js`, which sets `req.user`.

Only the Play feature is fully implemented today. Right now:
- The `User` table has no role, rating, or profile fields.
- The user's role lives only on the phone.
- Finished games do not change any rating.

## Goal

1. Store each user's **role** and **basic profile** in the database.
2. Give every user an **Elo rating** (start 1200) that updates **exactly once** when a **player-vs-player** game finishes.
3. Expose **profile APIs** so the mobile app can read and save the profile.
4. Return **role, rating, onboardingDone** at login.
5. Add a reusable **`requireRole`** middleware (RBAC guard) — create it, but don't apply it to any route yet.

Do **not** change how moves, clocks, sockets or AI games work, apart from the small additions below.

## Step 2 — Rating service (`src/services/rating.service.js`) — NEW

Export `applyRating(gameId)` and the pure helpers `expectedScore(a, b)` and `kFactor(gamesPlayed)`.

Rules:
- Only rate a game when **all** of these are true: `status = COMPLETED`, `gameType = PLAYER_VS_PLAYER`, `ratingApplied = false`, and both `whitePlayerId` and `blackPlayerId` are set.
- Make it **idempotent and race-safe**. Inside `prisma.$transaction`, first run `game.updateMany({ where: {...all conditions above}, data: { ratingApplied: true } })`. If `count === 0`, return `null` and do nothing else. Then the same game can never be rated twice, even if two requests finish it at the same time.
- Score for White: win = 1, loss = 0, draw or stalemate (`winnerId = null`) = 0.5.
- `expectedScore(a, b) = 1 / (1 + 10 ** ((b - a) / 400))`.
- `kFactor(gamesPlayed)` = 40 if `gamesPlayed < 30`, else 20.
- `change = Math.round(K * (score - expected))`, calculated separately for each player using that player's own K.
- Update both users (`rating: { increment: change }`, `gamesPlayed: { increment: 1 }`) and save `whiteRatingChange` / `blackRatingChange` on the game.
- Don't let a rating drop below 100 (clamp it).
- Return `{ whiteRatingChange, blackRatingChange, whiteRating, blackRating }` (the new ratings).
- Never throw on an AI, cancelled or aborted game. Return `null` instead.

## Step 3 — Call `applyRating` wherever a game ends

Add `const { applyRating } = require("./rating.service");` to both files.
In each place below, call `const ratingResult = await applyRating(game.id);` **right after** the `prisma.game.update(...)` that sets `status: "COMPLETED"` and **before** `emitToGame(...)`. Then add the rating info to the emitted payload:

```js
whiteRatingChange: ratingResult?.whiteRatingChange ?? null,
blackRatingChange: ratingResult?.blackRatingChange ?? null,
whiteRating: ratingResult?.whiteRating ?? null,
blackRating: ratingResult?.blackRating ?? null,
```

| File | Function / place | How the game ends |
|---|---|---|
| `game.service.js` | `getGameState` — the `liveTimes.isTimedOut` branch | Clock ran out while the player was away |
| `game.service.js` | resign function (uses `determineResult({ reason: "RESIGNATION" })`) | Resign |
| `game.service.js` | draw response function, `if (accept)` branch | Draw accepted |
| `move.service.js` | timeout branch near the top of the human move (`timeoutEnd`) | Clock ran out on a move |
| `move.service.js` | after the human move transaction, inside `if (gameStatus === "COMPLETED")` | Checkmate, stalemate or draw by move |

**Do not** call it in `finishAiGame`, the AI-move branch, `cancelGame` or `abortGame`.

```js
updateProfileSchema = z.object({
  name:        z.string().trim().min(1).max(80).optional(),
  role:        z.enum(["STUDENT", "PARENT"]).optional(),   // users may only self-select these two
  school:      z.string().trim().max(120).optional().nullable(),

  level:       z.enum(["Beginner", "Developing", "Advanced"]).optional().nullable(),
```

Turn empty strings into `null` before saving. Reuse the existing `validate()` pattern (`req.validatedBody`).

**Security rule.** If the body has `role` set to `COACH`, `SCHOOL`, `ORGANISER` or `ADMIN`, respond **403** with `{ code: "ROLE_NOT_ALLOWED", message: "You cannot choose this role" }`. Check this before zod runs, so the client gets a clear 403 and not a generic 400. Only an admin, working directly in the database, can give those roles for now.

## Step 7 — Auth changes

- `auth.middleware.js` → in `requireAuth`'s `select`, add `role: true, rating: true`, so `req.user.role` is available everywhere.
- `auth.service.js` → in the `authenticateWithGoogle` return value, add `role`, `rating`, `onboardingDone` to `user`. Make `getUserById` select these too.
- `auth.routes.js` → the `dev-login` response must return the same `user` shape (`role`, `rating`, `onboardingDone`).

Add `requireRole` to `auth.middleware.js` and export it:

```js
function requireRole(...roles) {
  return (req, res, next) => {
    if (!req.user) return res.status(401).json({ success: false, error: { code: "UNAUTHORIZED", message: "Authentication required" } });
    if (!roles.includes(req.user.role)) {
      return res.status(403).json({ success: false, error: { code: "FORBIDDEN", message: "You do not have permission to do this" } });
    }
    next();
  };
}
```

Don't apply it to any route yet. It's for Tournaments and Classes later.

## API contract (final)

### `GET /api/users/me` (auth required)
```json
{
  "success": true,
  "user": {
    "id": 1, "name": "Aarav Mehta", "email": "aarav@x.com", "avatarUrl": null,
    "role": "STUDENT", "rating": 1220, "gamesPlayed": 12,
    "school": "Greenwood High", "schoolClass": "5th grade", "level": "Beginner",
    "fideId": null, "parentName": "Jane", "parentEmail": "jane@x.com",
    "onboardingDone": true, "createdAt": "2026-10-01T10:00:00.000Z"
  }
}
```

### `PATCH /api/users/me` (auth required)
Request (every field is optional):
```json
{ "name": "Aarav Mehta", "role": "STUDENT", "school": "Greenwood High",
  "schoolClass": "5th grade", "level": "Beginner", "fideId": "",
  "parentName": "Jane", "parentEmail": "jane@x.com" }
```
Response: same shape as `GET /me`, with `onboardingDone: true`.
Errors: `403 ROLE_NOT_ALLOWED`, `400` validation error, `401` not logged in.

### `POST /api/auth/google` and `POST /api/auth/dev-login`
`user` now also has `role`, `rating`, `onboardingDone`.

### `GET /api/games/:gameId/result`
Adds:
```json
"rating": { "applied": true, "whiteRatingChange": 20, "blackRatingChange": -20 }
```
`players.white` / `players.black` also include `rating`.

### Socket `game:finished` (and `game:resigned`, `game:draw-accepted`)
Payload adds `whiteRatingChange`, `blackRatingChange`, `whiteRating`, `blackRating` (all `null` for AI games).
